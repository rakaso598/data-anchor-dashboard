# SWR vs Fetch: SWR를 사용해야 하는 이유

## 1. SWR이란?
SWR은 Vercel에서 만든 React용 데이터 패칭 라이브러리로, "Stale-While-Revalidate" 전략을 사용하여 사용자 경험을 개선합니다.

## 2. Fetch와의 차이점 및 SWR의 장점

### 1) 데이터 캐싱 및 자동 갱신
- **SWR**: 데이터를 캐시에 저장하고, 백그라운드에서 최신 데이터를 자동으로 가져와 갱신합니다.
- **Fetch**: 매번 네트워크 요청을 직접 관리해야 하며, 캐싱/갱신 로직을 직접 구현해야 합니다.

### 2) UX 개선 (빠른 응답)
- **SWR**: 캐시된 데이터를 즉시 보여주고, 최신 데이터로 자동 업데이트하여 사용자에게 빠른 피드백을 제공합니다.
- **Fetch**: 네트워크 응답을 기다려야 하므로, 첫 화면이 느릴 수 있습니다.

### 3) 자동 리패칭/리프레시
- **SWR**: 탭 포커스 복귀, 네트워크 재연결 시 자동으로 데이터를 다시 가져옵니다.
- **Fetch**: 이런 기능을 직접 구현해야 합니다.

### 4) 간단한 API
- **SWR**: `useSWR` 훅 하나로 로딩, 에러, 데이터, 캐싱, 갱신까지 모두 처리할 수 있습니다.
- **Fetch**: 상태 관리, 에러 처리, 로딩 처리 등을 직접 구현해야 합니다.

### 5) Next.js와의 궁합
- **SWR**: Vercel(Next.js 제작사)에서 공식적으로 지원하며, Next.js 프로젝트와 잘 어울립니다.

## 3. 언제 SWR을 써야 할까?
- 실시간 데이터 갱신이 필요한 대시보드, 테이블 등
- 여러 컴포넌트에서 동일 데이터를 공유/캐싱해야 할 때
- UX를 빠르고 부드럽게 만들고 싶을 때

## 4. 결론
- 단순한 1회성 데이터 패칭에는 fetch만으로 충분
- 하지만, 실시간성, 캐싱, 자동 갱신, UX 개선이 필요하다면 SWR이 fetch보다 훨씬 효율적이고 생산적임
